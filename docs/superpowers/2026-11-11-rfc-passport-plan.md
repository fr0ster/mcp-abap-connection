# Plan: the RFC wire carries the passport, names its errors, and never reopens a session

Bound by `2026-11-11-rfc-passport-goal.md` and `2026-11-11-rfc-passport-spec.md` (section
numbers below are the spec's). Branch `feat/rfc-passport`, worktree `.worktrees/rfc-passport`,
one PR for the whole task (#102). Release 22.0.0.

Every step is test first: the test that states the step's rule is written and seen red for the
right reason, then the change makes it green, then each named mutation is applied by hand, the
test watched going red, and the mutation reverted. A step is done when `npm run build`,
`npm run lint:check` and `npm test` are green and its mutations were watched red. Commits are
made by path, Conventional Commits, with the session's trailers, and pushed to the PR branch
before any external review. Only npm scripts run (`npm run test:ci -- <name>` for one file);
never `npx`, `npm exec` or `node_modules/.bin`.

**`npm test` and the live suites.** `rfc-connection.test.ts` reads `SAP_ENV_FILE`, else
`e19.env` from the repository root, and runs live when that file exists (Code). Before every
`npm test` in this plan, the worktree root holds no `*.env` file and `SAP_ENV_FILE` is unset,
so every live block skips with its reason. A live run happens only in step 10, on the owner's go.

## Steps

### 1. Gate: both dependencies on the registry

1. `npm view @mcp-abap-adt/sap-rfc-lite@0.4.0 version` and
   `npm view @mcp-abap-adt/interfaces-adt-connection@4.1.0 version` both answer their version.
   Until both do, no later step starts: the owner publishes them, and nothing is built against
   an unpublished copy or a local link.
2. Read the published `interfaces-adt-connection` 4.1.0 `dist/*.d.ts` inside `node_modules`
   once installed (step 2) and confirm the names the spec uses: `IAbapConnectionError`,
   `IRfcErrorInfo`, `RFC_RCS`, `RfcReturnCodeName`. A difference stops the plan and goes to the
   controller.

### 2. Baseline and ranges

1. In the worktree: `npm ci`; `npm run build`, `npm run lint:check`, `npm test` green on the
   unchanged sources.
2. `package.json`: `optionalDependencies` `@mcp-abap-adt/sap-rfc-lite` `^0.4.0` (stays
   optional); `dependencies` `@mcp-abap-adt/interfaces-adt-connection` `^4.1.0`. The lockfile
   is regenerated by `npm install`, never edited by hand.
3. Check the lockfile: no `"link": true`, every `resolved` on `registry.npmjs.org`, the two
   packages at 0.4.0 and 4.1.x.
4. `npm run build`, `npm run lint:check`, `npm test` green again (the stand-in conversations
   take two arguments and still conform — spec 6). Commit `chore(deps)`.

### 3. The header-name redaction without a regex (spec 7.2)

1. Test: the spec's table of names (redacted / kept), the Kelvin-sign name kept; and every name
   in it run against the old `SECRET_HEADER_PATTERNS`, copied into the test file as the oracle,
   asserting the same verdict.
2. Change: ASCII-only fold, then `includes` of the nine substrings; the patterns removed.
3. Mutations: `toLowerCase()` instead of the ASCII fold (Kelvin row red); drop each substring in
   turn (its row red).

### 4. The exception type without a regex, and the own-key lookup (spec 7.1)

1. Test: the spec's twelve rows, each also against the old regex as the oracle; the three
   own-key rows (`toString`, `constructor`, `__proto__` → 500) without the oracle, the
   departure named in the test's title.
2. Change: the linear scan; `Object.hasOwn(EXCEPTION_STATUS, type)` before the lookup.
3. Mutations: start the scan at the closing tag's `exc:type`; take the last `>` instead of the
   first; accept an empty capture; drop the `</exc:type>` check; drop `Object.hasOwn`.
4. Source test: no regex literal and no `RegExp` in `src/connection/RfcTransport.ts`.
   Mutation: put one regex back.

### 5. The SDK error as fields (spec 3)

1. Tests through `RfcTransport.send` with a stand-in conversation that rejects:
   - an `RfcLibError`-shaped and an `AbapError`-shaped object: the thrown `Error` has
     `rfc` deep-equal to the four fields, frozen, the message as today, no own `code`;
   - each field missing, of the wrong type, behind a getter, and a throwing Proxy: no `rfc`,
     the check throws nothing;
   - `codeString` not in `RFC_RCS` (`RFC_NOT_A_CODE`, `''`, `rfc_closed`): no `rfc`;
   - `nodeRfcError`, a `TypeError`: no `rfc`.
2. Change: `rfcErrorOf` at the `catch` in `carry()`; the error typed `Error &
   IAbapConnectionError`.
3. Mutations: drop `rfc`; drop each conjunct of the shape test in turn; drop the `RFC_RCS`
   membership; set `code` from `rfc.code`; read a getter.

### 6. The passport header (spec 6)

1. Tests:
   - `SAP-PASSPORT`, `sap-passport`, `Sap-Passport`: `call` gets the decoded `Buffer` as
     `{ passport }` in its third argument; no `HEADER_FIELDS` entry and no `logWire` line names
     the header;
   - no header: `call` gets exactly two arguments;
   - empty, odd length, a non-hex character first, in the middle and last: rejected, `call`
     not invoked, the message names `SAP-PASSPORT` and holds no character of the value;
   - the header twice (two spellings), with different and with equal values: rejected, `call`
     not invoked;
   - a request with the header, then one without: the second carries none;
   - stateful and non-stateful requests (kept and throwaway conversations) each carry it.
2. Change: find, check, decode, drop from the fields, pass; `IRfcConversation.call` gains the
   optional third parameter.
3. Mutations: compare names case-sensitively; keep the header in `HEADER_FIELDS`; always pass
   `{ passport: undefined }`; drop each value rule; quote the value; accept equal duplicates;
   take the first of two; keep the last passport on the wire.

### 7. Dead stateless conversations (spec 5)

1. Tests: a kept conversation whose call rejects and leaves `alive` false — the error carries
   `rfc`, neither `resetServerContext` nor `close` is called on it, the next non-stateful call
   opens a new one, the instance is not spent; a dead throwaway is not closed; a failure that
   leaves `alive` true is reset (kept) or closed (throwaway) as today.
2. Change: `carryOnKept` and `carryOnThrowaway` read `alive` after a rejected call.
3. Mutations: reset the dead kept one; close the dead throwaway; spend the instance.

### 8. The session lost on the stateful conversation (spec 4)

1. Wire tests (`RfcTransport` alone): a stateful call that rejects and leaves `alive` false
   throws `WireSessionLostError` with `rfc`, the conversation is dropped without `close()`;
   alive still true: the step-5 error, not `WireSessionLostError`; a `close()` that ran during
   the call: no `WireSessionLostError`; a concurrent stateful call meeting the
   closed-connection error: `WireSessionLostError` without `rfc`.
2. Base tests (`AdtOnPremConnector` + `RfcTransport`, and a stub wire that is not RFC throwing
   `WireSessionLostError`): the caller gets `code` `ADT_SESSION_REPLACED` with `rfc` intact
   through `answerCredentialFailure`; the next request `ADT_NOT_CONNECTED` with no `call` and
   no new conversation opened; `connect()` after it `ADT_NOT_CONNECTED`; `disconnect()`
   settles; a `WireSessionLostError` from a stale lease is rethrown and nothing is spent.
3. Change: `WireSessionLostError` in `authErrors.ts`, exported from `src/index.ts` beside
   `WireLogonError`; the wire throws it; `throwIfSessionDead` recognises it by class; the
   `IAdtTransport` doc comment names the marker.
4. Mutations: ignore `alive`; drop the generation check; reopen in `send`; drop `rfc` in the
   base; branch on `kind`; drop the lease check; spend on any RFC error.
5. The timer counter (`packageTimers`) and the no-deadline tests stay green: nothing new waits
   on a clock.

### 9. The live suite (spec 11)

1. A new block in `src/__tests__/rfc-connection.test.ts`, with its env file and skip rules
   (env lacking keys, sap-rfc-lite or the SDK missing — the reason in the block's title), plus
   a test-time skip naming `ZAC_SHR_DBG_PROBE` and the ADT clients' shared setup when the class
   answers `404`.
2. Test helpers: the debuggee passport from random terminal and IDE ids (the ADT client's
   layout, upper-case hex, never logged); the listener's answer and the conflict check read by
   plain search, as sap-rfc-lite's live helpers do.
3. The readiness re-check: `checkConflict=true` repeated with no pause until `409`, failing if
   the listener's poll settles first, under the owner-approved test-only exception to "no
   polling", with the same reason in its comment as sap-rfc-lite's live suite.
4. Cases: caught then terminated (`ADT_SESSION_REPLACED`, `rfc.key` and `rfc.codeString`
   `RFC_CLOSED`, group 4, code 6; then `ADT_NOT_CONNECTED`; the counting factory opened nothing
   after the error; the run answers `200`); not caught without the header.
5. Cleanup in `finally`: listener deleted, breakpoints cleared, every instance disconnected.
   Nothing of the env file, no id, no passport printed.
6. `npm test` with no env file: the block skips with its reason (seen in the output).

### 10. The live run (owner's go)

1. Say to the controller that the suite is ready for its live run, and wait for the go.
2. Before any logon: the operator's realm check — the target system's HTTP `401` realm names
   the expected system; the SAP NW RFC SDK path set; the session file named. Any password
   refusal stops everything.
3. `SAP_ENV_FILE=<file> npm run test:ci -- rfc-connection`; the whole RFC block, the new cases
   included, green. Record the result (no values) for the PR.
4. Afterwards: no listener and no breakpoint left (the cleanup's answers), every session logged
   off.

2. `docs/USAGE.md`: the same under the RFC wire and "Session Lifecycle".
