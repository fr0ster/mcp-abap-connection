**Rules for every step.**

- Test first: the test that states the step's rule is written and seen red for the right reason,
  the change makes it green, then each named break is applied by hand, the test watched going red,
  and the break reverted. A step is done when its gate is green and its breaks were watched red.
- Production code holds no type assertion (`as`), no `any`, no non-null `!`, no `@ts-ignore` /
  `@ts-expect-error`, and no regular expression; what the compiler can prove is not checked at run
  time (`@ts-expect-error` only in compile-only checks, on the exact line that must not compile).
- No timeout, retry, poll or timer is added anywhere; the stack's named resends stay as they are.
- Commits by path, Conventional Commits, with the session's two trailers, pushed to the PR branch
  before any external review; the PR's CI is checked after every push.
- Only npm scripts run (`npm run test:ci -- <name>` for one file in this repository); never `npx`,
  `npm exec` or `node_modules/.bin`.
- **`npm test` here can go live.** Before every `npm test` / `npm run test:ci` in this repository,
  neither the worktree root nor the main checkout's root holds a `*.env` file that a live suite
  reads, and `SAP_ENV_FILE` is unset — checked, not assumed — so every live block skips with its
  reason. A live run happens only in step 9, on the owner's go.
- Dependencies come from the registry only: no `file:`, `link:`, `npm link` or workspace link to
  another repository; after every install the lockfile is checked for `"link": true` and for any
  `resolved` not on `registry.npmjs.org`.
